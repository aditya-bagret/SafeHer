# 🛡️ SafeHer
### Real-Time Women Safety Navigation Using LightGBM-Driven Dynamic Temporal Heatmaps and Unified Risk-Coupled Route Recommendation

> **Paper target:** IEEE Access  
> **Dataset:** City of Chicago Crimes 2001–2025 (8.4M incidents)  
> **Model:** LightGBM spatial regressor · R² = 0.9997 · 14,129 grid cells  
> **Stack:** Python · Flask · React · Google Maps JS API

---

## What SafeHer Does

SafeHer overlays a **live crime risk heatmap** on Google Maps and recommends the **safest driving route** between two points — both powered by the same underlying LightGBM model. Dragging the hour slider updates the entire city's risk landscape in under 1 second.

```
risk(cell, hour, day) = spatial_risk(cell) × temporal_multiplier(hour, day)

spatial_risk     → LightGBM regressor (CDI percentile, R² = 0.9997)
temporal_mult    → direct lookup from violent crime rates (168 slots)
```

## API Reference

### `GET /api/heatmap`

Returns risk scores for all ~200m grid cells across Chicago.

| Param | Type | Default | Description |
|---|---|---|---|
| `hour` | int 0–23 | current hour | Hour of day |
| `day` | int 0–6 | today | Day of week (0=Mon) |
| `month` | int 1–12 | current month | Month (unused in model, kept for API compat) |

**Response:**
```json
[
  { "lat": 41.882, "lon": -87.627, "risk": 0.7341 },
  ...
]
```

---

### `GET /api/safe-route`

Returns ranked route alternatives scored by risk.

| Param | Type | Required | Description |
|---|---|---|---|
| `origin` | string | ✅ | Address or "lat,lon" |
| `destination` | string | ✅ | Address or "lat,lon" |
| `hour` | int 0–23 | ✅ | Hour of day |
| `day` | int 0–6 | ❌ | Day of week (default: today) |

**Response:**
```json
[
  {
    "route_index": 0,
    "label": "safe",
    "avg_risk": 0.2134,
    "duration_text": "18 mins",
    "distance_text": "4.2 mi",
    "polyline": "ekp~Fb...",
    "color": "#22c55e"
  }
]
```

Routes are sorted by `avg_risk` ascending — index 0 is always the safest.

## Model Architecture

### Why not classify per-incident severity?

Per-incident classification is an ill-posed problem: the same `(lat, lon, hour)` triple appears with both THEFT (severity 2) and ASSAULT (severity 4) labels — identical features, different targets. All tested models collapsed to predicting the majority class (accuracy ~0.38, R² < 0.17).

### Crime Danger Index (CDI)

```
CDI(cell) = violent_rate(cell) × log₁(1 + crime_count(cell))

violent_rate = crimes with severity ≥ 3 / total crimes in cell
base_risk    = CDI.rank(pct=True)   ← uniform 0–1 distribution
```

Aggregating to one row per grid cell eliminates label ambiguity. Converting to percentile rank gives a uniform distribution — exactly 30% of cells exceed 0.7.

### Two-Component Formula

```
risk(cell, hour, day) = clip(spatial_risk × temporal_mult, 0, 1)

spatial_risk  = LightGBM.predict(spatial_features)  → CDI percentile 0–1
temporal_mult = lookup[(hour, day_of_week)]          → violent crime rate ratio
```

Separating spatial and temporal components is the reason heatmap regeneration takes <1s instead of ~90s (CNN-LSTM baseline).

### Feature Importance (Top 5)

| Feature | Importance | Role |
|---|---|---|
| `violent_rate` | 13,880 | Fraction of violent crimes in cell |
| `violent_count` | 13,473 | Absolute violent crime count |
| `crime_count` | 8,940 | Total historical incidents |
| `is_domestic_rate` | 6,151 | Fraction of domestic crimes |
| `distance_to_police` | 3,985 | Km to nearest station |

## Novel Contributions

1. **CDI percentile target** — resolves class imbalance and label ambiguity (R² 0.17 → 0.9997)
2. **Unified risk grid** — heatmap colours and route scores computed identically
3. **Two-component model** — spatial ML + temporal lookup → <1s heatmap regeneration
4. **13-feature engineering** — violent rate, rolling 7-day rate, distance to police, location type
5. **Dynamic temporal heatmap** — city risk landscape changes hour-by-hour, first in women-safety literature
